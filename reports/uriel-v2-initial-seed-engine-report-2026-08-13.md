## 기술 요약

Uriel v2의 첫 번째 Python 기반 시드 실험 엔진을 구현하고 `main`에 반영했다. 이번 버전은 복잡한 예측 모델을 만들기보다, 다양한 시드 생성 규칙을 동일한 난수 생성기 위에서 재현 가능하게 비교하고 정답 기반 역산 실험을 병렬 수행할 수 있는 최소 연구 기반을 만드는 데 초점을 맞췄다.

구현과 실행 기반은 정상적으로 작동한다. `lotto.xlsx`의 1~1235회 데이터를 검증해 읽었고, 세 가지 시드 전략의 192회 walk-forward 평가와 20만 개 시드 역산을 멀티프로세스로 완료했다. 자동 테스트 8개와 설치형 CLI 실행도 모두 통과했다.

다만 현재의 단일 시드 forward 결과에서는 예측 신호가 확인되지 않았다. 가장 높은 `history-digest`의 평균 적중 수는 0.7917개로 무작위 단일 조합 기대값 0.8개와 사실상 같았다. `rolling-mix`는 한 번의 4-hit을 만들었지만, 무작위 단일 조합을 192회 실행해 적어도 한 번 4-hit 이상이 발생할 확률도 약 23.5%이므로 유의미한 신호로 볼 수 없다.

1235회 정답을 사용한 역산에서는 20만 개 시드 중 5-hit 시드 7개를 찾았다. 이론적 기대치는 약 5.75개이므로 결과는 난수 기준과 잘 맞는다. exact 6-hit이 없었던 것도 기대 개수가 0.025개에 불과해 자연스럽다. 따라서 역산 성공은 엔진이 올바르게 탐색한다는 증거이지 미래 정답을 예측했다는 증거는 아니다.

## 구현된 연구 기반

### 재현 가능한 번호 생성

Python 표준 `random`의 구현 변화에 영향을 받지 않도록 자체 `SplitMix64` 생성기를 사용한다. 시드에서 1~45 사이의 중복 없는 번호 6개를 선택하며, 같은 데이터와 옵션을 사용하면 운영체제나 Python 버전이 달라도 같은 결과가 생성된다.

시드 입력은 BLAKE2b를 사용해 64비트 정수로 압축한다. 전략 이름을 namespace로 분리해 서로 다른 전략의 입력이 우연히 같은 직렬화 구조를 갖더라도 동일 시드로 합쳐지지 않게 했다.

### 초기 시드 전략

| 전략 | 시드 입력 | 역할 |
|---|---|---|
| `round` | 대상 회차, variant | 과거 데이터가 없는 가장 단순한 기준선 |
| `history-digest` | 대상 회차, 최근 N회의 회차·번호 전체 | 과거 상태 전체를 하나의 안정적 시드로 압축 |
| `rolling-mix` | 번호 빈도, 회차별 가중 합, 최근 번호 간격, variant | 단순 통계 상태의 조합 가능성 확인 |

세 전략은 모두 미래 회차 정답이나 현재 회차 결과를 입력으로 사용하지 않는다. `predict`와 단일 후보 `evaluate`는 forward 경로이며, 정답을 사용하는 `reverse` 경로와 코드 및 로그상으로 구분된다.

### CLI와 실행 산출물

| 명령 | 기능 | 주요 산출물 |
|---|---|---|
| `inspect` | 엑셀 구조, 회차 범위, 최근 당첨번호 확인 | `data-summary.json`, `uriel.log` |
| `predict` | 지정 회차의 전략별 시드와 번호 생성 | `predictions.json`, `uriel.log` |
| `evaluate` | 과거 회차 walk-forward 평가 | `evaluation.csv`, `summary.json`, `uriel.log` |
| `reverse` | 알려진 정답에 대한 시드 구간 병렬 탐색 | `reverse-search.json`, `uriel.log` |

각 실행은 KST 기준 시간으로 구분된 `outputs/YYYYMMDD-HHMMSS-command/` 디렉터리에 저장된다. 긴 실행에서는 완료 작업 수, 진행률, 탐색 시드 수와 처리 속도를 콘솔과 파일 로그에서 동시에 확인할 수 있다.

### 워커 설계

- `ProcessPoolExecutor`를 사용해 CPU 연산을 여러 프로세스에 분산한다.
- `workers=auto`는 CPU 수를 기준으로 최대 8개 워커를 사용한다.
- 역산은 `[seed-start, seed-end)` 범위를 고정 크기 청크로 나눈다.
- 모든 청크를 한꺼번에 메모리에 적재하지 않고 워커 수의 두 배까지만 pending 상태로 유지한다.
- 각 청크는 0~6 hit 분포, 최소 적중 조건을 통과한 결과, 청크 내 최고 결과만 반환한다.
- 전체 결과도 제한 크기 heap으로 합쳐 장시간·대범위 실행 시 메모리 증가를 억제한다.

## 192회 forward 기준선은 무작위 수준을 넘지 못했다

평가 구간은 1044~1235회, 총 192회다. 각 회차에서는 해당 회차보다 이전 데이터만 사용했으며, 전략별 후보 수는 1개, 과거 참조 창은 최근 64회다. 보너스 번호는 적중 계산에서 제외했다.

단일 로또 조합이 정답 6개와 공유하는 번호의 이론적 기대값은 다음과 같다.

\[
E[hit] = 6 \times \frac{6}{45} = 0.8
\]

| 전략 | 평균 적중 | 무작위 0.8 대비 | 최대 적중 | 4-hit 이상 | 5-hit 이상 | 평균 위치 MAE |
|---|---:|---:|---:|---:|---:|---:|
| `history-digest` | 0.7917 | 98.96% | 3 | 0 | 0 | 6.8585 |
| `rolling-mix` | 0.7500 | 93.75% | 4 | 1 | 0 | 7.0313 |
| `round` | 0.6719 | 83.98% | 3 | 0 | 0 | 7.4575 |

정확한 회차별 분포는 다음과 같다.

| 전략 | 0-hit | 1-hit | 2-hit | 3-hit | 4-hit | 5-hit | 6-hit |
|---|---:|---:|---:|---:|---:|---:|---:|
| `history-digest` | 75 | 87 | 25 | 5 | 0 | 0 | 0 |
| `rolling-mix` | 85 | 76 | 26 | 4 | 1 | 0 | 0 |
| `round` | 86 | 85 | 19 | 2 | 0 | 0 | 0 |

세 전략 중 `history-digest`가 평균 적중과 위치 MAE에서 가장 나았지만, 평균 적중은 무작위 기대값보다 0.0083개 낮다. 현재 표본에서 관측된 차이는 실용적인 예측 우위로 해석할 수 없다.

`rolling-mix`의 4-hit 1회도 단독 성공 신호가 아니다. 무작위 단일 조합의 4-hit 이상 확률은 약 0.1393%이며, 이를 192회 실행해 한 번 이상 4-hit이 나올 확률은 약 23.5%다. 즉 충분히 자연스럽게 발생할 수 있는 결과다.

이 비교는 전략이 세 개뿐이고 각 전략의 정확한 값을 확인하는 것이 목적이므로 차트 대신 표를 사용했다. 현재 수치 밀도에서는 차트가 결론을 더 명확하게 만들지 않는다.

## 20만 시드 역산 결과는 생성기의 무작위 기대 분포와 일치했다

역산 대상은 1235회 정답 `(6, 7, 11, 15, 39, 43)`이다. 시드 구간 `[0, 200000)`을 4개 워커와 25,000개 단위 청크로 탐색했다.

- 탐색 시드: 200,000개
- 실행 시간: 약 0.370초
- 처리 속도: 약 539,867 seeds/s
- 5-hit: 7개
- exact 6-hit: 0개

| 적중 수 | 관측 개수 | 무작위 이론 기대 개수 | 관측 - 기대 |
|---:|---:|---:|---:|
| 0 | 79,967 | 80,112.93 | -145.93 |
| 1 | 84,777 | 84,825.45 | -48.45 |
| 2 | 30,428 | 30,294.80 | +133.20 |
| 3 | 4,511 | 4,488.12 | +22.88 |
| 4 | 310 | 272.93 | +37.07 |
| 5 | 7 | 5.75 | +1.25 |
| 6 | 0 | 0.025 | -0.025 |

상위 5-hit 시드는 다음과 같다.

| 순위 | 시드 | 생성 번호 | 위치 MAE |
|---:|---:|---|---:|
| 1 | 18,995 | 6, 7, 14, 15, 39, 43 | 0.500 |
| 2 | 9,844 | 6, 7, 8, 11, 39, 43 | 1.167 |
| 3 | 158,930 | 6, 7, 11, 15, 34, 39 | 1.500 |
| 4 | 128,303 | 7, 11, 15, 18, 39, 43 | 2.000 |
| 5 | 8,939 | 6, 11, 15, 22, 39, 43 | 2.500 |
| 6 | 140,753 | 7, 11, 15, 21, 39, 43 | 2.500 |
| 7 | 9,658 | 2, 6, 7, 11, 15, 43 | 6.167 |

5-hit 관측치 7개는 이론적 기대치 약 5.75개와 가깝다. 6-hit의 이론적 기대치는 20만 개당 약 0.025개이므로 exact 시드가 나오지 않은 것이 정상적인 결과다. 이 분포는 역산 워커와 결과 병합이 정상적으로 동작하고, SplitMix64 출력이 이 범위에서 뚜렷한 편향을 만들지 않았다는 초기 확인으로 사용할 수 있다.

## 거리 지표의 의미와 제한

엔진은 적중 수 외에 세 가지 거리 정보를 기록한다.

| 지표 | 정의 | 용도 | 제한 |
|---|---|---|---|
| `set_distance` | 두 6개 집합의 대칭 차이 크기 | 정확한 공통 번호 수를 거리로 표현 | 번호 크기 차이는 반영하지 않음 |
| `positional_mae` | 정렬한 번호를 같은 위치끼리 비교한 평균 절대 차이 | 정답 번호대와 위아래 근접성 확인 | 같은 번호가 실제로 일치했는지와 분리해서 봐야 함 |
| `signed_bias` | 정렬 위치별 `예측-정답`의 평균 | 전체적으로 높은 번호/낮은 번호 방향인지 확인 | 양수와 음수가 서로 상쇄될 수 있음 |

향후 계획했던 라인 그래프에는 `delta_1`~`delta_6`를 사용할 수 있다. 중앙선 0은 해당 정렬 위치의 정답과 동일함을 뜻하고, 양수는 정답보다 높은 번호, 음수는 낮은 번호를 뜻한다. 다만 이 그래프는 번호 위치의 근접도를 보여줄 뿐, 집합 적중 자체를 대신하지 않는다.

## 현재 결론과 해석 제한

### 확정할 수 있는 것

- 시드 전략을 추가하고 동일 조건으로 비교할 수 있는 최소 엔진이 완성됐다.
- 시드와 번호 생성 결과는 재현 가능하다.
- 장시간 탐색을 위한 프로세스 워커, 진행 로그, 제한 메모리 병합 구조가 동작한다.
- forward 평가와 winner-aware 역산 진단이 명령과 산출물 수준에서 분리됐다.
- 현재 세 가지 초기 시드 전략에는 무작위 대비 예측 우위가 보이지 않는다.

### 아직 확정할 수 없는 것

- 역산으로 찾은 시드 값에 회차 간 예측 가능한 시계열 구조가 있는지
- 특정 시드 변환이나 시드 군집이 다음 회차에도 일반화되는지
- 더 넓은 시드 범위에서 5-hit/6-hit 근접 시드가 비무작위적으로 집중되는지
- 복수 후보 시드 중 정답을 보지 않고 유효 후보를 선택할 수 있는지

정답으로부터 시드를 찾는 행위는 후향적 진단이다. 역산 시드, winner rank, winner pattern 같은 정답 인지 정보는 미래 회차의 직접 입력이나 후보 선택 기준으로 사용할 수 없다. 개발 구간에서 역산 시드의 변환 규칙을 먼저 고정한 뒤, 정답을 사용하지 않는 forward 방식으로 별도 구간에서 검증해야 한다.

## 다음 단계 권고

다음 단계는 새로운 복잡한 feature를 추가하는 것보다 역산 시드 자체의 회차 간 구조를 측정하는 편이 맞다.

1. **회차별 역산 시드 집합 생성**
   - 개발 구간의 각 회차에 대해 동일한 시드 범위를 탐색한다.
   - exact 6-hit, 5-hit, 위치 MAE 최저 시드를 별도 계층으로 저장한다.
   - 한 회차의 우연한 최소 시드 하나만 선택하지 말고 Top-K 집합을 보존한다.

2. **시드 시계열 구조 측정**
   - 연속 회차 seed delta
   - seed modulo 계열
   - 상·하위 비트 패턴과 Hamming distance
   - Top-K 시드 군집의 중심과 분산
   - 적중 계층별 시드 밀도

3. **변환 가설 동결**
   - 개발 구간에서 `이전 회차 역산 시드 → 다음 회차 forward 시드` 변환을 정의한다.
   - 정답을 본 뒤 변환식이나 선택 임계값을 수정하지 않는다.
   - 여러 변환을 비교할 때는 무작위 시드와 동일한 후보 수·탐색 예산을 사용한다.

4. **봉인 구간 유지**
   - 기존 Development `1044~1235`, Historical Reference `852~1043`의 역할을 구분한다.
   - Locked Holdout `660~851`과 Additional Blind `468~659`는 가설과 모든 선택 규칙이 고정될 때까지 열지 않는다.
   - 역산 진단 결과와 forward 검증 결과를 같은 성공 지표로 합치지 않는다.

5. **성공 기준 사전 정의**
   - 평균 적중 수보다 4+/5+/6 빈도와 무작위 대비 lift를 우선한다.
   - exact hypergeometric baseline과 동일 예산 Monte Carlo baseline을 함께 기록한다.
   - 여러 전략을 시험한 경우 다중 비교와 선택 편향을 명시한다.
   - 단일 5-hit 또는 6-hit 사례만으로 성공 판정을 내리지 않는다.

## 추가 확인 질문

- 역산은 모든 회차에서 고정 범위 `[0, N)`를 사용할지, 회차별 파생 범위를 사용할지
- 회차별 대표 시드를 하나로 압축할지, Top-K seed set을 시계열 단위로 유지할지
- exact 6-hit 탐색 비용이 커질 때 5-hit + 위치 MAE를 1차 검색 기준으로 허용할지
- 첫 개발 실험의 시드 상한을 1백만, 1천만, 또는 처리 시간 기준으로 정할지

이 네 가지를 정한 뒤 회차별 역산 데이터셋 생성을 시작하는 것이 Uriel v2의 다음 실질 단계다.

## 재현 명령

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

python -m uriel_v2 inspect --data lotto.xlsx --rows 10
python -m uriel_v2 predict --round 1236 --candidates 1 --history-window 64
python -m uriel_v2 evaluate \
  --start-round 1044 \
  --end-round 1235 \
  --candidates 1 \
  --history-window 64 \
  --workers 4
python -m uriel_v2 reverse \
  --round 1235 \
  --seed-start 0 \
  --seed-end 200000 \
  --min-hits 5 \
  --chunk-size 25000 \
  --workers 4

python -m unittest discover -s tests -v
```
